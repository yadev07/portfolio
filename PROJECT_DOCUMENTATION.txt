===============================================================

1. PROJECT PURPOSE
------------------
This project is a personal developer portfolio for Yadev Singh Nishad, a BCA
Computer Science student at Dev Sanskriti Vishwavidyalaya, Shantikunj,
Haridwar.

The website presents:
- Personal profile and introduction
- Technical skills
- Projects and project case studies
- Internship experience
- Education
- Achievements
- Conferences and workshops
- Contact details and contact form
- Optional interactive portfolio terminal

The project is designed so that portfolio content is stored in the data/ folder.
In normal use, content can be updated in data files without editing components.

7. CONTACT FORM FLOW
--------------------
The Contact component is a client component.

Flow:
1. Visitor enters name, email and message.
2. Client-side validation checks:
   - Name is at least 2 characters.
   - Email has a valid email format.
   - Message is at least 10 characters.
3. The browser sends a JSON POST request to /api/contact.
4. The API parses and validates the request again on the server.
5. The API applies a best-effort per-instance rate limit of 5 requests per
   minute per forwarded client address.
6. The API attempts Resend first when all Resend variables exist.
7. If Resend is not configured, it attempts CONTACT_WEBHOOK_URL.
8. If no provider is configured, it returns NOT_CONFIGURED with HTTP 503.
9. The UI displays success, configuration, validation or delivery errors.

Resend variables:
- RESEND_API_KEY
- CONTACT_TO_EMAIL
- CONTACT_FROM_EMAIL

Webhook variable:
- CONTACT_WEBHOOK_URL

Important Resend rule:
- CONTACT_TO_EMAIL is the recipient address.
- CONTACT_FROM_EMAIL is the authorized sender address.
- A normal Gmail address should generally not be used as the sender.
- Without a personal domain, use Resend's allowed testing sender if the account
  permits it, such as onboarding@resend.dev.
- The recipient may be restricted to the Resend account email on a new/testing
  account.
- For production, verify a domain in Resend and use an address on that domain.

If the API logs "Contact delivery failed with status 403", the request reached
Resend but Resend rejected it. Check:
- API key is active and belongs to the correct Resend project/team.
- Sender address is allowed or domain verified.
- Recipient is allowed for the account's current sending status.
- Variables are configured in the Production environment on Vercel.
- A redeploy was completed after changing variables.

The current route intentionally returns a generic delivery message to the
browser and does not expose the provider response body or secrets.

8. ENVIRONMENT VARIABLES
------------------------
Create .env.local for local development by copying .env.example.

Required for correct deployed metadata:
NEXT_PUBLIC_SITE_URL=https://your-deployed-domain.com

Choose one contact delivery option.

Option A - Resend:
RESEND_API_KEY=re_...
CONTACT_TO_EMAIL=your-recipient@example.com
CONTACT_FROM_EMAIL=authorized-sender@example.com

Option B - webhook:
CONTACT_WEBHOOK_URL=https://your-webhook-provider-endpoint

Never commit .env.local or any file containing real keys. The .gitignore file
ignores environment-specific files while keeping .env.example trackable.

10. VERCEL DEPLOYMENT
---------------------
1. Push the repository to GitHub.
2. Import the repository into Vercel.
3. Allow Vercel to detect Next.js automatically.
4. Add NEXT_PUBLIC_SITE_URL in the Production environment.
5. Add either Resend variables or CONTACT_WEBHOOK_URL.
6. Deploy the project.
7. After changing environment variables, redeploy Production.
8. For a clean dependency/build refresh, leave "Use existing Build Cache"
   unchecked during redeploy.
9. Test the live home page, projects pages, sitemap and contact form.

For a no-domain setup, a webhook service such as Formspree can be used instead
of Resend. Set CONTACT_WEBHOOK_URL and remove or clear all three Resend
variables so the route does not select the Resend branch first.

14. SECURITY NOTES
------------------
- Contact credentials are read only on the server.
- No API key is exposed to client-side code.
- Contact input is validated on both client and server.
- Submitted message content is sent as plain text.
- Resend response bodies are not logged.
- The contact endpoint has a basic in-memory rate limit.
- Environment files containing secrets are ignored by Git.
- Never put RESEND_API_KEY in a NEXT_PUBLIC_ variable.
